# Работа с секретами

### Требования
Для работы с шифратором необходимо

- добавить зависимость
```groovy
dependencies {
    testImplementation "ru.autotestframework.plugins:encryptor:${VERSION}"
    // с 2.15 версии плагин перенесен в 
    testImplementation "ru.psb.at-tools:encryptor:1.0.0"
}
```

#### Ключ-пароль

Ключ-пароль - пароль, с использованием которого шифруются все секреты в проекте. Выступает в роли первичного токена для доступа к зашифрованным данным
Минимальная длина - 5 символов

Ключ-Пароль можно задать следующими способами
- с использоваванием **системной** переменной PROJECT_SECRET,
- передать через систему сборки gradle или maven
- передавать значение пароля самостоятельлно напрямую в методы encryptor-а (метод доставки в приложения на усмотрение инженера АТ, но должен быть без хранения значений в открытом виде и без утечек(sout/log и т.д.))

#### Алгоритм использования секретов (файлов и строк) и дешифратора

*Было*

---Подготовка

//....
---Тесты (классы и feature-файлы)

I. прочесть файл с секретом, использовать строковое значение

*Стало*

---Подготовка

//....
I. Создайте util-ьный класс с public static void main с телом, в котором будут вызываться соответствующие методы шифрования (encryptFile / encrypt) из класса Encryptor для всех секретов (строки-пароли и файлы), таким образом сгенерируются шифрованные секреты(файлы / строки).
1. Файлы
   удалить файлы с секретами и поместить в проект шифрованные файлы с секретами вместо удаленных
2. Строки
   На месте строк-секретов (проперти-файлы, Java-код) поместить шифрованные строки
   ---Тесты (классы и feature-файлы)
   II. прочесть файл-ы или строки используя дешифратор (контекстные функции, встраивание в свой код доп методов и т.д.)

Note. Добавление строк в файлы-секреты делается аналогичным образом - расшифрование файла в новый файл, добавление необходимых данных/строк, шифрование

#### [Примеры использования - шифрование и дешифрование](https://gitlab-01/automated-testing-technology/libraries/core-base/-/tree/develop/plugins/encryptor/src/test/java)

#### Шифрование
Encryptor использует [128 битный AES](https://ru.wikipedia.org/wiki/AES_(стандарт_шифрования)) с режимом [CBC](https://en.m.wikipedia.org/wiki/Block_cipher_mode_of_operation#CBC)

Шифруются отдельные файлы и строки, после применения шифрования к хранимым значениям и добавлением логики для дешифрования в местах использования проверяется работоспособность тестов, в которых секрет задействован

#### Расшифрование. Примеры

Для чтения файлов необходимо использовать readDecryptedFile (чтобы не тратить ресурсы на многократную дешифровку больших файлов-секретов)
Для чтения строк необходимо использовать decrypt.

#### Использование переменных приложения тестов

При хранении в пропертях (кастомных, например bd.properties или фреймворка (framework.properties) можно хранить в зашифрованном виде (например с приставкой encrypted) и при старте приложения создавать дешифрованные переменные, к которым и будет происходить дальнейшее обращение.

Примеры.

1. Кастомный properties configuration класс
```
public String getPassword() { 
    return Encryptor.decrypt(password);
}
```

2. Кастомизация для контекста

```Java

    public void login(String password) {}
//либо для allure
    @Step 
    public void setClientUserToken(@Param(mode = HIDDEN) String password){}

```
